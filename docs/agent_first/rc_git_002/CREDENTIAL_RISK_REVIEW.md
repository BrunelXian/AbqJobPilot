## 根因与最小修正

`run_022/verify_cleanup.py` 曾先将整个 lifecycle JSON 收入内存，然后检查已有报告的泄漏，再把包含凭据的内存对象写入新 CLEANUP。检查未覆盖即将写出的内容。新增纯函数 `run_022/audit_redaction.py`，对 `credential/ciphertext/operator_token` 精确字段递归脱敏；记录其他事实不变。没有执行旧清理脚本，也没有运行其删除逻辑。

现有 CLEANUP 的 45 个字段被替换为明确标记，所有其他 JSON 值保持一致；字段位置和前后文件摘要在 `REDACTION_RECEIPT.json`，无原文值。负向测试改用不可认证的明确哑字符串制造明文降级，继续验证拒绝与错误不含秘密，原随机生成/加密断言仍保留。新增嵌套、幂等、原事实保留的脱敏回归。

逐字节扫描本轮开始已有文件（不扫描 `.git`、不解密），未发现其他这 45 个历史值的工作树副本。此结论不覆盖历史对象、远端缓存、他人克隆或未纳入范围的外部路径。

## 待单独决定的历史处置

不确认当前存在有效信任关系，也不声称已撤销。若被授权的实例审查发现任一值仍被活动服务或可启动配置信任，应先撤销/轮换该**精确实例**的连接材料及必要的操作者材料；不可批量停止历史 owner。本轮未访问这些外部实例。

可接受保留历史的依据应是：责任人确认来源均为无监听服务的隔离测试、源配置已失效/删除、没有复制到受信任实例，并明确接受已公开 DPAPI 容器的残余风险。当前证据支持低于“已泄露生产密钥”的风险等级，但不满足将随机材料归为固定哑数据并自动免责。

若无法确认，另行批准针对性撤销/轮换及历史治理方案。历史重写不能代替撤销，工作树脱敏也不能代替历史重写；本轮不决定或实施远端强制操作。
